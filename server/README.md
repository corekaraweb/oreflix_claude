# OREFLIX サーバーサイド (PHP)

一般的なPHP対応レンタルサーバー(さくらのレンタルサーバ、ロリポップ、Xserverなど)にNode.jsなしでデプロイするための、YouTube Data APIキーと再生リスト設定を扱うバックエンドです。

## なぜ必要か

このバックエンドを追加する前は、APIキーと再生リストは各訪問者のブラウザのlocalStorageに保存されていました。それではレンタルサーバーで公開しても「自分だけの設定」になってしまい、全訪問者に同じ再生リストを見せることができず、しかもAPIキーをブラウザ側で管理する構造でした。

このバックエンドは:
- APIキーをサーバー上のファイルにのみ保存し、**ブラウザには一切送信しません**(フロントエンドはYouTube APIを直接呼ばず、必ずこのPHPプロキシ経由で呼び出します)。
- 再生リストの一覧をサーバー側の設定として保持し、**全訪問者が同じ内容**を見られるようにします。
- パスワード付きの `/admin/` 画面から、サイト管理者だけが設定を変更できます。

## ディレクトリ構成と配置場所

```
server/
├── private/            ← Webからアクセスさせてはいけないディレクトリ
│   ├── Config.php
│   ├── Security.php
│   ├── .htaccess        (直接アクセスを拒否する保険)
│   └── config.json      (初回アクセス時に自動生成。APIキー・再生リスト・管理者パスワードのハッシュを保存)
└── public/             ← Webサーバーの公開ディレクトリにアップロードする内容
    ├── bootstrap.php
    ├── api/
    │   ├── config.php    (公開: 再生リストIDの一覧を返す)
    │   └── youtube.php   (YouTube Data APIへのプロキシ。APIキーをここで注入)
    └── admin/
        ├── index.php     (管理画面: 初期設定・ログイン・設定変更)
        └── logout.php
```

**推奨されるサーバー上の配置**(`public_html` が公開ディレクトリの場合):

```
~/                          (ホームディレクトリ、または public_html の一つ上)
├── private/                 ← server/private の中身をここにアップロード(Web公開ディレクトリの外)
└── public_html/
    ├── index.html            ← npm run build で生成した dist/ の中身
    ├── assets/...
    ├── api/                   ← server/public/api の中身
    ├── admin/                 ← server/public/admin の中身
    └── bootstrap.php          ← server/public/bootstrap.php
```

`server/public/bootstrap.php` は `private/` を「`public_html` と同じ階層にある `private` フォルダ」として探します。契約しているレンタルサーバーが `public_html` の外にファイルを置けない場合は、`private` フォルダを `public_html/private` に置いても動作します(同梱の `.htaccess` が直接アクセスを拒否します)。ただし可能な限り公開ディレクトリの外に置いてください。

## 初期セットアップ手順

1. `npm run build` でフロントエンドをビルドし、`dist/` の中身を `public_html/` 直下にアップロードします。
2. `server/public/` の中身(`bootstrap.php`, `api/`, `admin/`)を `public_html/` にアップロードします。
3. `server/private/` の中身を、`public_html` の一つ上の `private/` フォルダにアップロードします(上記の配置図を参照)。
4. ブラウザで `https://あなたのドメイン/admin/` にアクセスします。初回は「管理者パスワードを設定してください」という画面が表示されるので、8文字以上のパスワードを設定してください。
5. ログイン後の管理画面で、YouTube Data APIキーと、表示したい再生リストのURL(またはID)を登録してください。
6. トップページ(`https://あなたのドメイン/`)を開くと、登録した再生リストが全訪問者に表示されます。

## セキュリティ上のポイント

- `config.json` にはAPIキーと管理者パスワードのハッシュ(平文パスワードではない)が保存されます。パーミッションは`0600`で作成されますが、`private/`ディレクトリ自体を公開ディレクトリの外に置くことが最も重要な対策です。
- 管理画面はCSRFトークンで保護され、ログイン失敗が15分間に5回続くとそのIPを15分間ロックします。
- 本番運用では必ずHTTPS(SSL)を有効にしてください。HTTP接続の場合、管理画面に警告が表示されます。
- `api/youtube.php` は設定済みの再生リストID以外を受け付けず(任意の再生リストを取得するプロキシとして悪用されるのを防止)、IPごとに簡易レート制限もかかっています。
- YouTube APIのレスポンスはサーバー側で一定時間キャッシュされます(再生リスト情報: 1時間、動画一覧: 10分、動画詳細: 30分)。これにより、訪問者が増えてもAPIクォータの消費を抑えられます。

## ローカル開発

PHPをインストールした上で、2つのサーバーを同時に起動します。

```bash
npm run dev:php   # PHPバックエンドを http://localhost:8080 で起動
npm run dev       # Viteフロントエンドを起動(/api, /admin へのリクエストは自動的にPHP側へ転送されます)
```
